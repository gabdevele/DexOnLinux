# NM-owned P2P and direct WFD probe — 2026-10-21

## Result

Gate 0 did **not** pass, but the P2P protocol path did.

### NM-owned PBC

- `P2P-PROV-DISC-PBC-REQ` arrived.
- `P2P-GO-NEG-SUCCESS role=client freq=5825 wps_method=PBC`.
- `WPS-SUCCESS` and `P2P-GROUP-FORMATION-SUCCESS`.
- iwlwifi then crashed:

```text
iwlwifi: Microcode SW error detected. Restarting 0x0.
iwlwifi: FW error in SYNC CMD LINK_CONFIG_CMD
iwlwifi: Device error - SW reset
```

- The hardware restarted, the P2P group was lost, and the base STA was
  deauthenticated. Internet returned only after the driver reprobe.
- NM-owned P2P chooses the GO channel; NetworkManager 1.46 has no frequency
  property for `wifi-p2p`.
- `wpa_cli set p2p_oper_channel 2437` returned `OK`, but wpa_supplicant logged
  `P2P: Own oper channel update failed: -1`.

### Direct backend

- With `P2P_CONNECT ... pbc freq=2437 go_intent=0`:
  - `P2P-GO-NEG-SUCCESS role=client freq=2437`;
  - `P2P-GROUP-STARTED ... client ... 192.168.49.200 ... go_ip_addr=192.168.49.1`;
  - RTSP `connected`, `video_formats`, `streaming`;
  - 60 s stability, `ping 192.168.49.1` 0% loss, internet 0% loss;
  - base STA stayed on 5200 MHz/160 MHz.
- This worked only while NetworkManager was `SIGSTOP`ped.
- Marking only the NM Wi-Fi P2P device `managed no` did **not** prevent the
  immediate local deauth after `P2P-GROUP-STARTED`.
- Without the freeze, the group dies immediately after group start. The direct
  backend itself is sound; NM is still removing/detaching the group interface.

## Implications

- SIGSTOP was initially diagnostic, but the user explicitly accepted a controlled
  session-scoped freeze when no runtime detach worked without a reboot.
- The direct backend now pre-ups the group netdev during GO negotiation and
  adds the address only after `P2P-GROUP-STARTED` (commit `5a51325`).
- Runtime attempts to detach NM without a reboot did not work:
  - `nmcli device set p2p-dev-... managed no` did not release NM's monitor;
  - `systemctl reload NetworkManager` did not fix the P2P device;
  - the strict-unmanaged drop-in requires a reboot, which the user rejected.

## Design update (accepted)

- Use the direct backend with `freq=2437`.
- Keep NetworkManager and wpa_supplicant running. The helper sends `SIGSTOP` to
  NetworkManager only immediately before `P2P_CONNECT` (not while waiting for a
  phone) and sends `SIGCONT` on every exit path.
- A separate small watchdog process, in its own session, resumes
  NetworkManager if the helper is killed or crashes.
- This keeps the established station connection and internet usable; it does
  not stop or restart NetworkManager, and it does not replace wpa_supplicant.
- The NM-owned backend is not implemented because NM 1.46 cannot select the
  P2P frequency and the AX201 firmware crashes on the 5 GHz group.
- The `packaging/networkmanager/99-dexonlinux-p2p.conf` drop-in is **not**
  part of the product path; it was removed because applying it requires a
  reboot.
